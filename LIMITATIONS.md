# Known Limitations

> iterate is built incrementally and honest about what each version does **not** do yet.
> This register tracks every deliberate limitation and the version that lifts it. It pairs
> with the roadmap in [BUILD_LOG.md](BUILD_LOG.md). A few limits are **permanent by design**
> (security policy), and are marked as such rather than scheduled for removal.

Version map (from the roadmap): v0.2 sandboxed code-gen + the multi-agent cell-by-cell
core (Supervisor, coding agent, Summarizer) · v0.3 interactive runs (terminal UI, chat,
pause/resume/stop, notebook Q&A, standing rules) · v0.4 Researcher + Critic specialists +
agent picks metric/model · v0.5 prompts · v0.6 DL/vision · v0.7 cost-constrained · v0.9
infer features/target + MCP discovery (absorbs v0.8) · v1.0 one-sentence input + benchmark
+ dashboard (absorbs v0.10). "backlog" below = tracked for after v1.0.

## Metrics & evaluation

| Limitation (today) | Lifted at | Notes |
|---|---|---|
| Metric vocabulary is what scikit-learn can score (54 names: 12 curated plus every applicable sklearn scorer). Anything outside it still raises "unknown metric". | **widened v0.4**; closed by design | Direction is DERIVED from sklearn's own scorer registry, never hand-written and never supplied by a model: sklearn's scorers are all higher-is-better by construction, with loss metrics carrying a -1 sign. That is what keeps the set open to whatever the Researcher proposes while still making it impossible for an agent to invert the loop, since direction drives what banks as best and when a run stops. Clustering scorers are excluded (they compare two label assignments, not a prediction against a target). The always-computed PANEL stays at 12 so history is comparable and cheap; a selected metric outside it is computed on top. |
| A probability metric needs an estimator that can produce probabilities. On the `--spec` path an estimator without `predict_proba` (SVC at its default, Ridge) scores labels only, so a probability primary fails with a reason rather than silently reporting nothing. | **by-design** | The code-gen path is unaffected: the agent chooses its own model and the finish gate rejects a submission missing `probabilities.csv`, so it is told before the iteration is lost. |
| Single train/holdout split; no cross-validation. The same holdout is reused to select across all iterations (mild selection bias). Since v0.6 the split can be yours: `--train` plus `--holdout` seals the holdout exactly as given, for every family on the code path (the `--spec` fast lane keeps `--data`). | **partly v0.4**; CV backlog | The v0.4 Critic reviews every experiment and FLAGS a gain that looks like luck (most often a holdout score far above the validation trail the session printed), which surfaces the symptom. It does not remove the cause: reusing one holdout to select across iterations is structural, and only a k-fold/CV selection option fixes it. That stays on the backlog, and the Critic deliberately cannot veto on this basis — a suspicion is not grounds for a model to overrule the measurement. |
| The primary metric is fixed at run start and cannot change mid-run, including when the agent picks it itself (v0.4 Dial A). | **by-design** | Every score in Memory and every cross-run baseline carry-over is measured with one ruler. A metric that changed mid-run would leave the history silently incomparable and would break the prior-best inheritance a later run depends on. It is validated once at startup, then frozen. |
| The Critic vetoes only on a LEAK it can point at in the submitted code; a suspected mirage is recorded but still banks if it improves. | **by-design** | A leak is a verifiable defect, so acting on it is safe. Whether a gain is real is probabilistic, and the sealed holdout is already this project's ruler — letting a 12B overrule it would put a model back into the control flow that direction, the guard stack and duplicate-hashing were all deliberately kept out of. A false leak report also throws away a real result, so the prompt pushes hard toward reporting nothing when the evidence is not in the code. `--no-critique` skips the review. |
| Threshold-style levers (class weighting, threshold tuning) are withheld from the fallback menu and rejected in a brief when the primary metric is threshold-free (`roc_auc`, `average_precision`, `log_loss`, `brier`). | **by-design v0.4** | Measured across five datasets: tuning the decision threshold moves `f1` by ~0.02 and moves `average_precision` and `roc_auc` by EXACTLY 0.0000 every time, because a ranking metric is invariant to the threshold by construction; class weighting is the same story about ten times weaker. Three certification runs picked `average_precision` and then spent iteration 2 on class weighting. Telling the supervisor in its prompt was not enough — the note reaches the prompt and the floor model briefed it anyway — so it is a guard, which is the same lesson the June EDA-ledger revert produced: guards beat prompt nudges on weak models. |
| A run that ends with "no candidate beat the baseline" does not tell you whether the agent failed or the dataset had nothing left to find. | backlog | The two are indistinguishable from the summary table, and they call for opposite responses. Measuring the difference needs a brute-force ceiling per dataset, which costs compute the user did not ask for, so it is not in the product. It is measured internally instead (`evals/`, 2026-08-08): of six datasets, three sit at their measured ceiling already, where finding nothing is the correct answer. Surfacing this to users needs its own design. |
| A prompt run scores one answer against a known set. A free-text answer column (summaries, rewrites, translations) is REFUSED rather than scored. | backlog | Measured: three genuinely correct summaries score 0.0000, because the only thing being compared is exact string equality. A confident meaningless zero is worse than an error, so the run stops before it starts and says why. `--allow-free-text` scores on exact matches for anyone who wants it. Free-form generation needs a similarity metric iterate does not have. |
| More than 50 distinct answers drops the enum that makes an out-of-vocabulary reply impossible; replies are then matched by text. | by-design | A 150-item list of options in every single call is not a prompt, it is a catalogue. Full CLINC150 still runs — the cost is more unparseable answers, and the run says so at startup rather than leaving it to be discovered. Narrowing the label set usually scores better. |
| A prompt run is one model call per record, and a local Ollama serialises them by default. | by-design | Measured: 8 concurrent workers give a 1.10x speedup, so a 300-record pass costs 300 sequential calls — about 16 minutes on a 12B. Setting `OLLAMA_NUM_PARALLEL` is worth more than anything in the harness; the run says so once, with the number. |
| A prompt run scores a closed set of answers or a number. Both are supported; free-form generation is not. | **v0.5** | Classification and regression are what LLM tasks in production mostly are, because both produce something structured enough to act on. Summarising, rewriting and translation need a similarity metric iterate does not have, and are refused rather than scored — see the free-text row above. |
| On a numeric target, an unusable answer is scored as the TRAINING MEDIAN. | **by-design v0.5** | Measured across four options on a 300-row rating task with 10% refusals: DROPPING the unusable rows scores BETTER than answering them honestly (rmse 0.691 against 0.701), so a prompt could win by refusing the hard rows. The median penalises on both error and correlation metrics, and unlike a worst-case substitution a handful of refusals cannot swamp the score. The count is reported either way. |
| `pearson`, `spearman` and `kendall` are computed by scipy, not scikit-learn. | **by-design v0.5** | None of the three is an sklearn scorer. They are curated the same way `rmse` and `brier` already are, and scipy is a hard dependency of sklearn so nothing new is installed. They are selectable as a primary metric but deliberately NOT in the always-computed panel: adding them would change the recorded metric set of every regression run that has already happened. |
| A correlation metric cannot see a calibration error. | **by-design** | A prompt that rates everything three points too high scores pearson 1.000 and rmse 3.000. For a rating task that is usually the right verdict — an offset calibrates away, an ordering does not — but it is a real blind spot, which is why the error metrics stay available and the Researcher chooses per dataset. |
| Every stored baseline and ceiling was recorded on scikit-learn 1.8.0, and scikit-learn 1.9 moves them, so v0.6.0 requires scikit-learn below 1.9. | **v0.7** | Measured on the same source and the same split: mobile_price accuracy 0.9450 on 1.8.0 and 0.9250 on 1.9.1, churn f1 0.5776 and 0.5647, heart 0.8850 and 0.8933. A plain `HistGradientBoostingClassifier` script with no iterate code shows the same 0.945 against 0.925, and 1.8.0 beside the newer numpy 2.5.3 and pandas 3.0.6 still gives 0.945, so scikit-learn 1.9 alone is the cause. It is not new in v0.6: v0.5.0 on PyPI resolves 1.9.1 today. The cost of a cap is that it can force a downgrade in an environment other packages share. v0.7 re-measures the stored numbers on 1.9 and lifts it. |
| Single primary metric (single-objective); no multi-objective trade-offs. | **v0.7** | Cost-constrained optimization: best score within a serving budget. Since Day 1 of the v0.7 sprint every winner leaves with its serving price, or the reason it has none; the budget wall that refuses a candidate is the next day. |
| A table winner's serving price comes from the shape of its pipeline, not from timing the winner itself. The estimator class names on the last error-free cell that names one, up to the cell that wrote the predictions, pick a family (linear, boosting, tree ensemble, nearest neighbours, svm, mlp), and each family carries one single-row latency measured on the corpus on this Mac, doubled as the margin. A pipeline that names no estimator the table knows is unpriced, and says so. | **v0.7** | A code-path winner never reaches the host, only its predictions do, so nothing can time it there; timing it inside the kernel means a harness-owned `submit()` for tables, which changes the prompt contract a 12B has learned. Measured 2026-09-25, scikit-learn 1.8.0, two threads, the slowest one-row predict over laptop_price, mobile_price, heart_risk and adult_income: linear 2.9 ms, tree ensemble 12.2 ms, boosting 4.5 ms, nearest neighbours 3.2 ms, svm 2.9 ms, mlp 2.8 ms. |
| Requests an hour on a machine come from a benchmark rate, and no cloud CPU was measured. The three pinned backbones were timed at 64, 128 and 224 px on an Apple M5 with two threads and that stands in for a 2-vCPU box; a custom stack scales from resnet18's rate by multiply-adds; a GPU row gets a rate only where a plain-PyTorch batch-1 number was published (the T4), and the L4 and A10 rows price one box with no capacity claim, because their published numbers are INT8 TensorRT. | **v0.7** | An independent measurement on an AWS c7i.xlarge puts resnet50 at 224 px at about 44 ms against the 49.8 ms measured here, so the stand-in is close on the one box that was checked, and every profile says which of the three it used. Fixed overhead dominates small images: resnet18 at 64 px takes 6.9 ms, not the 2.1 ms that scaling its own 224 px time by multiply-adds would give, three times more, which is why the table is measured per size rather than derived. A ten-minute run on a real t3.small would replace the stand-in. |
| A prompt whose model under test runs locally is priced by memory fit only: the cheapest GPU box whose VRAM holds the weights at 4-bit, one box, and the line says whether it keeps up with the rate is not estimated. A local model with no size in its name is unpriced. | **v0.7** | Tokens a second for a 7B to 13B model on a cloud GPU has published community numbers (llama.cpp on a T4 about 46 a second, on an A10G about 108) but no vendor number, so the capacity is not claimed. A target on a backend the price table has no rows for is unpriced, and the profile says no public price was found for it; Groq is one, since it retired its self-serve Llama models in August 2026. An `openai-compatible` backend prices as the cloud its base URL points at, and as nothing when the URL is a private endpoint. |
| An image winner that is the agent's own torch network is priced from timm's table when the name the agent passed is in it, at the run's image size, and is unpriced with the reason when it is not. | **v0.7**, since Day 2 | 927 of the 1,101 names in `timm_models.txt` are in the table. A wrapped network, a changed head or a name timm never benchmarked is not, and the line says so. One of the 11 live image sessions counted in the floor-model row below ended on its own network. |
| Machine prices are live only after `iterate prices refresh`. AWS's own price list is about 300 MB per region, so it is fetched only by that command, streamed and reduced once, never in the background of a run; Azure's open API is walked at a refresh and in the background at the start of a run with `--cloud azure` when the cache is a day old; GCP's catalog needs a key this version does not take, so its four shipped rows stand. Offline with no cache, the snapshot shipped in the package (13 machines, 2026-09-25) stands in. API model prices (12 rows) have no machine-readable feed anywhere and stay a dated snapshot. API rate limits, egress, storage, load balancers and idle scaling to zero are not modelled: a served model is priced as one always-on box, or as tokens times price. | **v0.7**; GCP through a key is the first cut of Day 2 | Measured 2026-09-26: AWS's us-east-1 CSV is 303 MB and reduces to 1,303 machines in under two minutes; Azure's eastus walk is 9 pages of 1,000 rows in 3 seconds and yields 948 machines. Every row keeps its source and the day it was read, every priced line says per cloud whether it read a refreshed list or the shipped one and when, and `iterate prices show` prints the same. |
| Azure's price API carries no vCPU or memory, so specs are read from the SKU name through Azure's naming convention: the family letter sets memory per vCPU (D and DC 4 GB, E and EC 8, F 2, a D with an `l` 2), the B v1 sizes come from a table, and the GPU comes from the accelerator token (T4, A10, A100, H100) at the vCPU counts that carry a whole GPU. Families the table does not know are dropped, not guessed. | **v0.7** | Measured 2026-09-26 on eastus: 1,677 Linux hourly SKUs, 948 sized, 729 dropped (M, L, FX, HB, DS, A, ND, the fractional A10 sizes and the RTX PRO 6000 SKUs among them). Azure's resource SKU API would give the specs but needs an account. |
| A machine nobody measured gets its capacity from a rule: one request uses about two threads, so a box serves one worker per two vCPUs, and its capacity is the 2-vCPU rate times that. The basis line says so. GPU machines other than the T4 still price one box with no capacity claim. | **v0.7** | Serving frameworks run one worker per few cores by design, so the rule is how they are deployed rather than a measurement of any box. A measured rate per box would come from a benchmark run on a real instance. |
| A network the Researcher names is sized from timm's published table (weights, multiply-adds, and milliseconds per image at batch 1 on one CPU), and 927 of the 1,101 names in `timm_models.txt` are in it. timm measured with `torch.compile`; a plain `load().predict()` runs eager, and the two differ most on networks with large depthwise convolutions and layer norms: convnext_tiny at 224 px is 14.5 ms compiled on timm's i9 and 527 ms eager on this Mac. The Pricer scales timm's times relative to resnet50 measured here and the basis says a plain deployment can be slower. | **v0.7** | The 174 names not in the table (the largest ViTs and a few families timm never benchmarked) are unpriced with the reason. A compiled deployment would make timm's relative times the right ones; measuring the eager gap per network family is a later calibration. |

## Models & preprocessing

| Limitation (today) | Lifted at | Notes |
|---|---|---|
| Metric names given to the agent are scorer names, and the importable scikit-learn symbol differs (`average_precision` vs `average_precision_score`). | **fixed v0.4** | The coder is now told the importable function alongside the metric. Before the fix it wrote `from sklearn.metrics import average_precision` and burned 16 cells across the certification runs. Two scorers whose functions are private (the likelihood ratios) are excluded from the vocabulary entirely, because a metric an agent cannot compute is not one worth offering. |
| The agent's kernel runs the SAME interpreter iterate is installed in. | **fixed v0.4** | It previously started the machine's registered `python3` kernelspec, which on macOS is the Command Line Tools interpreter: measured here as python 3.9.6 / scikit-learn 1.6.1 against the project's 3.12.12 / 1.8.0. Auto-install targets `sys.executable`, so installed packages never reached the kernel either. On a machine without a system scikit-learn every run would have failed outright. |
| A CSV that is not UTF-8 loads via a latin-1 fallback. | **fixed v0.4** | `pd.read_csv` assumes UTF-8 and raises `UnicodeDecodeError` otherwise. Any European export with an accented name is latin-1, so a user's first contact was a decoding traceback on a file that opens fine in a spreadsheet. |
| A cp1252 file's Windows-only characters are silently mangled rather than rejected. The euro sign is the common one. | backlog | Found 2026-08-08 while building the adversarial shape corpus, which could not write its own "euro sign" fixture: latin-1 has no euro codepoint at all. A spreadsheet export with a real € is cp1252, where that byte decodes under our latin-1 fallback as an unprintable control character. The file loads and the run proceeds, so this is worse than the crash it replaced in one specific way — it is invisible. Only affects the text of categorical values, never a number or a target, so it degrades a feature rather than a score. |
| Boolean feature columns no longer abort the run. | **fixed v0.4** | `SimpleImputer` rejects bool dtype, and a frame mixing bool with string columns makes it take the numeric path and fail on the first string. Any dataset with a yes/no column stored as a real boolean failed at the BASELINE, so the run aborted before iteration 1. |
| In an image session every try trains on 80% of the training images and is checked on the fifth of each class held back, while the baseline trained on all of them, so a try's own number carries a small handicap against the baseline it is compared with. The sealed holdout, which decides the run, is scored on all of it either way. | **by-design** | The same share tables hold back, for the same reason: a try needs a number of its own before it is submitted, and the fold is the same images in every session and after a restart, so two tries are like for like. Measured on EuroSAT: the plain CNN 0.9398 on the fold against 0.9496 for the baseline, a resnet18 fine-tune 0.9720 against 0.9785; Flowers102 tied at 0.9743. Refitting on all the images at submit would double every fit, 35 s to 205 s each. |
| A session that writes cheap cells spends neither of its budgets, so a model that thrashes can hold one iteration for the full 90 minute wall ceiling. | **v0.7** | The fit deadline charges kernel-execution seconds only, on purpose, so a user is not billed for the model's latency, and the six-consecutive-errors cut is reset by any cell that runs. Measured live on 2026-09-21, cyclone_wind iteration 3: 26 cells in 40 minutes alternating sub-second successes with `AttributeError: 'Fit' object has no attribute ...` and `SyntaxError: incomplete input`, with the fit budget still on 468 of its 2,700 seconds. What stops it is the 5,400 second wall ceiling or `max_cells=50`, whose comment ("time is the real bound") is what this run falsified. The run's best is untouched and the wasted iteration is labelled, so the cost is wall clock. v0.7: count a cell that neither trains nor submits against a smaller cap. |
| An image session's own code is bounded only by the cell timeout: `seconds_left()` is advice the agent's loop may ignore, and a model that trains past it is killed, not stopped politely. A rendered image notebook re-executes only where iterate itself is installed, because its opening cell imports `iterate.core.vision_session`. | **v0.7** | `fit()` plans its epochs against the budget and stops between them; own torch code cannot be planned that way. gemma4:12b called `seconds_left()` in 2 of 3 measured own-code cells. The device memory a killed cell held is freed at the top of the next cell, not at the kill. |
| An image run saves a network only when a `fit()` try wins. If the winner is the agent's own torch code, or no try beat the baseline, the run folder has no `best_model.pt` in v0.6.0. | **v0.7** | The run says so in one line at the end, with the reason. When the winner is the agent's own network, `best.json` has `artifact_path: null` and `best.ipynb` holds the code that built it. When no try beat the baseline there is no winner, so the run writes no `best.json` at all, only that line. An own network is not saved because the name the agent passes as `model=` is not the architecture it built: a wrapped model, a changed head or another timm version fails to load only later, in the user's app, and a name that starts with `hf_hub:` makes a network call at load time. The plain-CNN baseline is never saved, so its numbers and every stored ceiling stay as they were. |
| `best_model.pt` is as trusted as the run that wrote it. | **by-design** | `load()` opens it as plain weights (`weights_only=True`), refuses a torch older than 2.6, where such a file could still run code, and checks every metadata field before it builds anything: format, backbone, task, image size, class count, label scale, mean and std, the layer settings the network is rebuilt from (`layers`, `head` and `drop_stages`, each refused in the same plain words a fit would give), and that the weights are a table of tensors. The host copies the file out of the kernel only when its sha256 is the one the session wrote into recipe.json, and the end of the run delivers it only when it matches the winning try's. That proves the file is the one the session recorded. It does not prove the session was honest: a cell could write both files. The delivered file is read-only so a re-run notebook cell that writes `best_model.pt` fails loudly; that guards against an accident, not against someone who wants to replace it. |
| Loading a saved network needs iterate-ai, torch and torchvision installed in the app. | backlog | `pip install 'iterate-ai[vision]'`. `load()` imports only numpy, PIL and torch, and a test proves pandas, scikit-learn, lightgbm and the agent stay out of the process. They are still installed, because they are iterate's core dependencies. The file is a plain dict of metadata and a `state_dict`, and the network is rebuilt from the recipe inside it, so opening it by hand means rebuilding the same network by hand. A file in another saved-network format is refused, and the refusal says to open it with the iterate-ai version that wrote it. |
| An app on macOS that loads a saved network and also fits lightgbm in the same process can crash or hang. | **by-design containment** | The same wall as inside iterate: torch and lightgbm each ship their own OpenMP runtime. `load()` never imports lightgbm, so the app only meets it if the app uses lightgbm itself. Run the two in separate processes. |
| A probe winner's saved network can disagree with its `predictions.csv` on a near-tie. | **by-design** | A probe's predictions come from a float64 scikit-learn head, and the saved network carries that head as a float32 layer. Measured on the round-trip fixture: probabilities differ by 3.9e-08 and every predicted class is the same. On thousands of holdout images one or two near-ties can flip, so a reloaded probe's score can differ from `best.json` by that much. A trained fit reloads exactly on the device it trained on: the measured gap is 0.0 through the real kernel on a Mac's GPU, and 5.6e-17 against the written CSV on the round-trip fixture. Loading on another device (a Mac's GPU against a CPU) can move probabilities in the last decimals. |
| `layers=` and `head=` take four layer names and nothing else: `conv` (a convolution, batch norm and ReLU together), `pool`, `dropout`, `linear` (with a ReLU). There are no residual or attention blocks, no choice of activation, and no way to leave the batch norm out. | v0.7 | Four names fit in one prompt sentence and a 12B cannot forget a norm or an activation it is never asked to write. The kernel and stride on `conv` are there so a paper's 5x5 or strided layer can be written without growing the prompt. Measured on an EuroSAT slice (960 train, 240 holdout, 64 px): `conv(32) pool conv(64) pool conv(128) pool conv(256) pool` scores 0.8542 against the plain CNN's 0.8000, so the grammar reaches something the fixed baseline does not. A residual block needs a second shape of module and a second set of saved weight names, and it is v0.7 with a measured rung behind it. |
| `drop_stages` counts STAGES, not layers, and takes 0, 1 or 2. On resnet50, `drop_stages=1` throws away about 15M of the 23.5M pretrained weights. | **by-design** | "Remove the last two layers" in a paper usually means the pooling and the classifier, which `head=` alone already replaces; this setting is the bigger move and it is named for what it does. The widths are pinned and checked on every backbone: resnet18 512/256/128, resnet50 2048/1024/512, convnext_tiny 768/384/192. No ready line ever writes it on its own. A torchvision that renames or resizes a stage is refused by name rather than cut in the wrong place. |
| One learning rate trains the head and the backbone. There is no separate rate for a new head on a pretrained network. | backlog | The usual advice is a smaller rate for pretrained weights than for a randomly started head, and `unfreeze` is the coarse version of it: `head` trains the head alone, `last_block` adds the last stage that is left. A second rate is a second lever for the supervisor to spend an experiment on, and the run has a small budget of them. |
| `head_init="probe"` needs `drop_stages=0` and a head with no linear layer in it. | **by-design** | The probe is one linear layer fitted on the WHOLE backbone's features, so it only copies into a final layer of that width. With a stage dropped or a linear layer added the widths no longer match, and the recipe is refused with the two things to change rather than silently started from noise. A head of dropout alone still starts from the probe. |
| A typed ask opens three levers and no more in v0.6.0: `layer-stack`, `custom-head` and `last_block`. An ask for another backbone, a timm model by name, an image size or a number of epochs is a steer the supervisor may take, not a lever the harness opens. | v0.7 | Each opener has to be certified on a live run, and these three are the ones the hold exists for. The other classes already open on this run's own numbers, so an ask there only changes which open entry is briefed, which is what the guidance message has always done. A named timm model by ask is about three lines of code and a fourth opener to certify, so it waits. |
| A one-shot ask the supervisor passes over is not re-queued. It opens the next experiment only. | **by-design** | An ask that stayed open would skip the closed filter every iteration and pin the rest of the run on a stack the model keeps mis-copying, which is the blocker a skeptic measured. Typing it again is one line and the run tells you what it read each time. Measured on gemma4:12b, 10 calls at the run's own temperature: the first brief took the ask both times it was tried, 10 of 10 for `layer-stack` and 10 of 10 for `custom-head`, so passing over it is rare. |
| Two near-identical stacks count as two different values. `conv(32) pool linear(256)` and `conv(33) pool linear(256)` are both untried as far as the ladder is concerned. | backlog | The tried-value set compares the canonical text, which is what `fit()` would actually build: two stacks that differ by one width really are two different networks, and a distance rule would need a threshold nobody has measured. The cost is that a model retyping a width by one digit spends an experiment on a network nobody chose, and the ready line's "copy the stack exactly as it is written here" is what pushes against that. |
| A research finding opens a layer class only when the cited abstract states widths at all and every number in the stack appears in it, which will be seldom, because abstracts rarely list widths. The stack must be in the suggestion's own technique: one written into the rationale beside it opens nothing, and neither does a line that compares two networks. | **by-design** | A 12B copies the example it is shown, so an invented network arriving with a real paper pinned to it is the failure this rules out, and an unearned citation is the one thing the Researcher exists to prevent. The width rule is there because an abstract that lists no width still carries numbers (input size, batch size, epochs, dropout, classes) that an invented stack matches by luck: measured on gemma4:12b, exactly that kept an invented network 5 of 5 before the rule. Measured, 5 calls each: on a real EuroSAT-shaped paper list no stack was written at all; on a planted abstract that writes one out the stack came back and was kept 5 of 5; on a planted abstract making the same claim with no width, the model invented a stack 5 of 5 and all 5 were dropped. The suggestion itself survives if it names a model as well, with the widths taken out of its layers, because the model name and the citation are what the paper really earned. |
| A layer class opened by a research finding is rarely the one briefed. Measured 0 of 20 on gemma4:12b: the entry sits on the ready line and the model briefs a class with a number from a fit line behind it instead. | monitor | A typed ask reaches the planner twice, on the ready line and as the guidance message, and takes the brief 20 of 20. A finding reaches it once, and this model weighs one line of the ready line lightly against its own reading of the history. Type the stack in if you want the run to try it. |
| A session carries its LAST fit forward, not its best. After a losing try, the next `fit()` in the same session starts from the losing recipe. | monitor | It is what the printed "recipe now" line says and what the session file records, so nothing is hidden, and the run's own best is protected by the keep-best guard either way. Resetting to the best on a loss would make two cells in a row read differently from what they print. The supervisor's next experiment always starts from the carried best, so this only reaches within one session. |
| An image run's folder grows by the size of one network, up to about 111 MB. | **by-design** | Measured at 10 classes: the plain CNN 0.4 MB, resnet18 44.8 MB, resnet50 94.4 MB, convnext_tiny 111.4 MB. | One-shot code-gen writes the whole pipeline blind; aggressive feature engineering can silently produce near-zero scores (NaN/inf, single-class predictions) the agent can't foresee. | **addressed in v0.2 cell-by-cell** | The cell-by-cell session catches it mid-session (the agent inspects intermediate output + a model-ready assert runs before `.fit()`), instead of writing the pipeline in one shot. |
| The cell-by-cell carry-forward hands the next experiment a concatenated blob of the winning session's cells (not a labeled, staged pipeline). | **works; typed handoff on the backlog** | The staged coder prompt treats the starting point as REFERENCE ONLY (find its score, rebuild as small cells, beat it), which the validation runs show working. A typed `Session` handoff is tracked on the backlog. |
| Code-gen winners return predictions, not a pickled model. | **permanent** | Security/portability; the readable artifact is the v0.2 notebook deliverable. |
| No cloud-GPU compute backend (local + e2b only). | backlog | The `ComputeBackend` interface for one was first on the v0.6 cut list and was cut on 2026-09-20. An image run trains on this machine, and `--compute e2b` refuses it. |

## Interactive runs (v0.3)

| Limitation (today) | Lifted at | Notes |
|---|---|---|
| Messages take effect at the next safe boundary (a cell finishing, or just before planning), never mid-cell. The ack is instant; delivery can lag a slow cell or a slow LLM turn. | **by-design** | An interrupt is a kill, not a pause; the cell boundary is where state is coherent, gates run, and the kernel survives. |
| Only the bare words `pause` / `resume` / `stop` are controls (trailing punctuation tolerated). "please stop the run" routes as guidance, with only the ack text hinting otherwise. | monitor | The intent router deliberately has no stop authority: a misclassified sentence must never be able to end a run. |
| Message intent is classified by the same (possibly small, local) model that supervises. A failed or garbled classification defaults to the least-destructive route: a steer for the work in front of us, and the console says so. | **by-design** | Interpretation degrades, it never crashes or blocks the run. |
| Standing rules are run-scoped (they do not survive a restart) and lean-capped: 3 rules, 90 chars each; steers cap at 200 chars per message. | persistence: backlog | Dense injected context measurably regresses small models (the reverted EDA-ledger experiment); the caps are a feature. |
| In-run Q&A answers from the CURRENT run's experiments only; it cannot answer about previous runs. | TBD | Deliberate: iteration numbers restart every run, and cross-run answers were confidently wrong. An offline query surface is on the backlog. |
| Token-level streaming of the model's output did not ship (planned for v0.3, cut for the release). | backlog | The transcript streams per cell and per event, not per token. |
| The `--spec` fast lane stays non-interactive. | **by-design** | The frozen v0.1 path is kept cheap and predictable. |
| The interactive UI needs a foreground terminal; piped, scripted, CI, and backgrounded (`... &`) runs are plain and non-interactive. | **by-design** | A backgrounded process reading its terminal would be suspended by the OS; iterate detects this and stays hands-off. |

## Permanent by design (not limitations to remove)

- **Never execute user-provided source code.** A `--source` notebook/script is read as text only and reconstructed; the sandbox runs the agent's OWN generated code, never the user's. (Security policy.)
- **The harness/loop is bounded.** Human-approval gates and bounded autonomy are features, not limits to remove.
