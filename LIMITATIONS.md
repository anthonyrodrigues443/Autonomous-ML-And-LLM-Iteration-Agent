# Known Limitations

> iterate is built incrementally and honest about what each version does **not** do yet.
> This register tracks every deliberate limitation and the version that lifts it. It pairs
> with the roadmap in [BUILD_LOG.md](BUILD_LOG.md). A few limits are **permanent by design**
> (security policy), and are marked as such rather than scheduled for removal.

Version map (from the roadmap): v0.2 sandboxed code-gen + the multi-agent cell-by-cell
core (Supervisor, coding agent, Summarizer) · v0.3 interactive runs (terminal UI, chat,
pause/resume/stop, notebook Q&A, standing rules) · v0.4 Researcher + Critic specialists +
agent picks metric/model · v0.5 prompts · v0.6 DL/vision · v0.7 cost-constrained · v0.9
infer features/target + MCP discovery (absorbs v0.8) · v1.0 one-sentence input + benchmark
+ dashboard (absorbs v0.10). "backlog" below = tracked for after v1.0.

## Metrics & evaluation

| Limitation (today) | Lifted at | Notes |
|---|---|---|
| Metric vocabulary is what scikit-learn can score (54 names: 12 curated plus every applicable sklearn scorer). Anything outside it still raises "unknown metric". | **widened v0.4**; closed by design | Direction is DERIVED from sklearn's own scorer registry, never hand-written and never supplied by a model: sklearn's scorers are all higher-is-better by construction, with loss metrics carrying a -1 sign. That is what keeps the set open to whatever the Researcher proposes while still making it impossible for an agent to invert the loop, since direction drives what banks as best and when a run stops. Clustering scorers are excluded (they compare two label assignments, not a prediction against a target). The always-computed PANEL stays at 12 so history is comparable and cheap; a selected metric outside it is computed on top. |
| A probability metric needs an estimator that can produce probabilities. On the `--spec` path an estimator without `predict_proba` (SVC at its default, Ridge) scores labels only, so a probability primary fails with a reason rather than silently reporting nothing. | **by-design** | The code-gen path is unaffected: the agent chooses its own model and the finish gate rejects a submission missing `probabilities.csv`, so it is told before the iteration is lost. |
| Single train/holdout split; no cross-validation. The same holdout is reused to select across all iterations (mild selection bias). | **partly v0.4**; CV backlog | The v0.4 Critic reviews every experiment and FLAGS a gain that looks like luck (most often a holdout score far above the validation trail the session printed), which surfaces the symptom. It does not remove the cause: reusing one holdout to select across iterations is structural, and only a k-fold/CV selection option fixes it. That stays on the backlog, and the Critic deliberately cannot veto on this basis — a suspicion is not grounds for a model to overrule the measurement. |
| The primary metric is fixed at run start and cannot change mid-run, including when the agent picks it itself (v0.4 Dial A). | **by-design** | Every score in Memory and every cross-run baseline carry-over is measured with one ruler. A metric that changed mid-run would leave the history silently incomparable and would break the prior-best inheritance a later run depends on. It is validated once at startup, then frozen. |
| The Critic vetoes only on a LEAK it can point at in the submitted code; a suspected mirage is recorded but still banks if it improves. | **by-design** | A leak is a verifiable defect, so acting on it is safe. Whether a gain is real is probabilistic, and the sealed holdout is already this project's ruler — letting a 12B overrule it would put a model back into the control flow that direction, the guard stack and duplicate-hashing were all deliberately kept out of. A false leak report also throws away a real result, so the prompt pushes hard toward reporting nothing when the evidence is not in the code. `--no-critique` skips the review. |
| Threshold-style levers (class weighting, threshold tuning) are withheld from the fallback menu and rejected in a brief when the primary metric is threshold-free (`roc_auc`, `average_precision`, `log_loss`, `brier`). | **by-design v0.4** | Measured across five datasets: tuning the decision threshold moves `f1` by ~0.02 and moves `average_precision` and `roc_auc` by EXACTLY 0.0000 every time, because a ranking metric is invariant to the threshold by construction; class weighting is the same story about ten times weaker. Three certification runs picked `average_precision` and then spent iteration 2 on class weighting. Telling the supervisor in its prompt was not enough — the note reaches the prompt and the floor model briefed it anyway — so it is a guard, which is the same lesson the June EDA-ledger revert produced: guards beat prompt nudges on weak models. |
| A run that ends with "no candidate beat the baseline" does not tell you whether the agent failed or the dataset had nothing left to find. | backlog | The two are indistinguishable from the summary table, and they call for opposite responses. Measuring the difference needs a brute-force ceiling per dataset, which costs compute the user did not ask for, so it is not in the product. It is measured internally instead (`evals/`, 2026-08-08): of six datasets, three sit at their measured ceiling already, where finding nothing is the correct answer. Surfacing this to users needs its own design. |
| A prompt run scores one answer against a known set. A free-text answer column (summaries, rewrites, translations) is REFUSED rather than scored. | backlog | Measured: three genuinely correct summaries score 0.0000, because the only thing being compared is exact string equality. A confident meaningless zero is worse than an error, so the run stops before it starts and says why. `--allow-free-text` scores on exact matches for anyone who wants it. Free-form generation needs a similarity metric iterate does not have. |
| More than 50 distinct answers drops the enum that makes an out-of-vocabulary reply impossible; replies are then matched by text. | by-design | A 150-item list of options in every single call is not a prompt, it is a catalogue. Full CLINC150 still runs — the cost is more unparseable answers, and the run says so at startup rather than leaving it to be discovered. Narrowing the label set usually scores better. |
| A prompt run is one model call per record, and a local Ollama serialises them by default. | by-design | Measured: 8 concurrent workers give a 1.10x speedup, so a 300-record pass costs 300 sequential calls — about 16 minutes on a 12B. Setting `OLLAMA_NUM_PARALLEL` is worth more than anything in the harness; the run says so once, with the number. |
| A prompt run scores a closed set of answers or a number. Both are supported; free-form generation is not. | **v0.5** | Classification and regression are what LLM tasks in production mostly are, because both produce something structured enough to act on. Summarising, rewriting and translation need a similarity metric iterate does not have, and are refused rather than scored — see the free-text row above. |
| On a numeric target, an unusable answer is scored as the TRAINING MEDIAN. | **by-design v0.5** | Measured across four options on a 300-row rating task with 10% refusals: DROPPING the unusable rows scores BETTER than answering them honestly (rmse 0.691 against 0.701), so a prompt could win by refusing the hard rows. The median penalises on both error and correlation metrics, and unlike a worst-case substitution a handful of refusals cannot swamp the score. The count is reported either way. |
| `pearson`, `spearman` and `kendall` are computed by scipy, not scikit-learn. | **by-design v0.5** | None of the three is an sklearn scorer. They are curated the same way `rmse` and `brier` already are, and scipy is a hard dependency of sklearn so nothing new is installed. They are selectable as a primary metric but deliberately NOT in the always-computed panel: adding them would change the recorded metric set of every regression run that has already happened. |
| A correlation metric cannot see a calibration error. | **by-design** | A prompt that rates everything three points too high scores pearson 1.000 and rmse 3.000. For a rating task that is usually the right verdict — an offset calibrates away, an ordering does not — but it is a real blind spot, which is why the error metrics stay available and the Researcher chooses per dataset. |
| Single primary metric (single-objective); no multi-objective trade-offs. | **v0.7** | Cost-constrained optimization: best score within a serving budget. |

## Models & preprocessing

| Limitation (today) | Lifted at | Notes |
|---|---|---|
| Metric names given to the agent are scorer names, and the importable scikit-learn symbol differs (`average_precision` vs `average_precision_score`). | **fixed v0.4** | The coder is now told the importable function alongside the metric. Before the fix it wrote `from sklearn.metrics import average_precision` and burned 16 cells across the certification runs. Two scorers whose functions are private (the likelihood ratios) are excluded from the vocabulary entirely, because a metric an agent cannot compute is not one worth offering. |
| The agent's kernel runs the SAME interpreter iterate is installed in. | **fixed v0.4** | It previously started the machine's registered `python3` kernelspec, which on macOS is the Command Line Tools interpreter: measured here as python 3.9.6 / scikit-learn 1.6.1 against the project's 3.12.12 / 1.8.0. Auto-install targets `sys.executable`, so installed packages never reached the kernel either. On a machine without a system scikit-learn every run would have failed outright. |
| A CSV that is not UTF-8 loads via a latin-1 fallback. | **fixed v0.4** | `pd.read_csv` assumes UTF-8 and raises `UnicodeDecodeError` otherwise. Any European export with an accented name is latin-1, so a user's first contact was a decoding traceback on a file that opens fine in a spreadsheet. |
| A cp1252 file's Windows-only characters are silently mangled rather than rejected. The euro sign is the common one. | backlog | Found 2026-08-08 while building the adversarial shape corpus, which could not write its own "euro sign" fixture: latin-1 has no euro codepoint at all. A spreadsheet export with a real € is cp1252, where that byte decodes under our latin-1 fallback as an unprintable control character. The file loads and the run proceeds, so this is worse than the crash it replaced in one specific way — it is invisible. Only affects the text of categorical values, never a number or a target, so it degrades a feature rather than a score. |
| Boolean feature columns no longer abort the run. | **fixed v0.4** | `SimpleImputer` rejects bool dtype, and a frame mixing bool with string columns makes it take the numeric path and fail on the first string. Any dataset with a yes/no column stored as a real boolean failed at the BASELINE, so the run aborted before iteration 1. |
| Spec path limited to allow-listed installed libraries (scikit-learn / XGBoost / LightGBM). | **v0.2** | Superseded by the code-gen path (Day 4): the CodeProposer has **no library allow-list** — it writes a `train_and_predict` and imports whatever it wants; we install its imports before running. The spec path keeps the allow-list as the cheap/fast/reliable option. |
| Spec-path preprocessing is fixed (median impute + one-hot). | **v0.2** | The code-gen path lets the agent preprocess freely. Spec-path flexibility itself: TBD. |

| Limitation (today) | Lifted at | Notes |
|---|---|---|

The distinct-value cap now applies to integer targets as well as float ones. Nothing that previously worked changes, because every working dataset has 20 or fewer distinct target values; the only targets affected are ones that used to crash. Recorded as a backlog item on Day 5 and deferred on the reasoning that a fix would change existing splits, which measurement later showed to be wrong. |

| `--metric` is optional: omitted, the Researcher proposes one over the papers it fetched and the harness validates it. An explicit `--metric` always wins. | **lifted v0.4** | Every failure path — unknown name, wrong task for the target, dead network, model that will not answer — falls back to exactly what v0.3 would have run (f1 / f1_macro / rmse by target type), so the dial can only upgrade a working run, never break one. The choice is printed with its reason before the first experiment: a tool that silently picks your evaluation metric is worse than one that asks. |
| `--target` + features must be given. | **v0.9** | Infer from the data + a one-line description (the v0.8 milestone, shipping inside the v0.9 release). |
| Full one-sentence input not yet possible. | **v1.0** | Autonomous discovery. |

## Agent architecture

| Limitation (today) | Lifted at | Notes |
|---|---|---|
| ~~The Researcher, Critic and Summarizer appear in the terminal UI as dimmed log lines, not styled events.~~ | **lifted in v0.5** | Specialist lines are matched on the message and styled (Researcher cyan, Critic and the verdict guards yellow, Summarizer blue) rather than dimmed with the rest. Matched on text rather than emitted as events because these agents are orchestrated by the harness, not by the coder's event channel; giving them real events means threading a callback through `run_supervised`, which is a bigger change than the problem. |
| ~~Research cache files record the papers but not the QUERY that fetched them.~~ | **lifted in v0.5** | `.iterate/research/{source}-{hash}.json` now stores `{query, source, limit, fetched_at, papers}`. Reads stay backward compatible with the pre-v0.5 bare list, so an existing cache is not invalidated by upgrading. |
| Multi-agent core is Supervisor + coding agent + Summarizer + Researcher + Critic. | **complete v0.4** | The v0.2 default path is already multi-agent (re-sequenced from the original v0.4 plan, see DECISIONS.md). Researcher (literature grounding) and Critic (eval hardening) land at v0.4. The `--spec` path stays single-proposer. |
| On a weak local model, expect 1-2 iterations per run to end as honestly-labeled duplicates or measured null results. | **by-design (the capability floor)** | A deterministic guard stack (grounded briefs, no-op gates, duplicate hashing, floor submissions) detects, labels, and converts weak-model waste rather than hiding it; certified across 21 instrumented gemma4:12b runs. The residue that remains is the model's floor, not silent process failure: each such iteration is stamped in memory and annotated in its notebook. |
| Local-model tool-calling occasionally drops a tool call (qwen3:14b). | mitigated; ~v0.4 | Mitigated with retries; cloud backend is the reliable path; multi-agent specialists reduce per-call load. |
| Local 14B is unreliable at acting on its own error tracebacks (observed: claims to fix a missing import, ships the same `NameError` again). Modeling/exploration depth scales with the backend model. | use a cloud backend | A/B (2026-06-04) confirmed: a 70B explored models far more, and a feature-engineering prompt unlocked real FE. 14B is the floor; `--backend groq/openai/…` goes deeper. The v0.2 cell-by-cell session + breakers (repeated-cell, same-error) + v0.4 Critic reduce reliance on one blind call. |
| Thinking mode (`--think`, ollama backends) applies to the CODER only and is OFF by default. | **by-design** | Tested live (2026-06-08): a thinking trace crowds out the single tool call that strict roles (supervisor, summarizer) must emit, and on the coder it made cells MORE monolithic (plans in-head, dumps one cell). Kept as an opt-in debugging instrument — the trace renders as a "Model reasoning" cell in the notebook. |
| Staged R&D cells are validated on the gemma4:12b floor only; qwen3:14b has not been re-run since the worked-example prompt landed. | **monitor** | The 2026-06-07 "staging is model-bound" conclusion was overturned for gemma by the worked-example prompt (monolithic cells 31–35% → <1%); whether the same prompt stages qwen is untested. |
| **On gemma4:12b the supervisor never sets an optional boolean, so `want_research` and `want_inspect` are both inert on the floor model.** | **honest floor-model limit, measured 2026-08-10** | Zero asks across 18 live iterations in three runs, and zero across three targeted probes including one built to invite it (34 unlabelled numeric columns, stalled three iterations). This is not specific to the v0.5 inspect field: `want_research` shipped in v0.4 with the same shape and behaves the same way, so the literature grounding a floor-model run actually gets is the automatic iteration-1 pass and nothing else. Both fields work on any model that sets them, and cost nothing when unset. The deterministic alternative — the HARNESS deciding to inspect from the data profile rather than asking — is the shape this codebase usually reaches for and is re-homed to v0.6 rather than improvised the night before a release. |
| **The prompt path has no dead-lever guard, so the agent can spend several iterations refining one move that has already lost.** | **v0.6** | The tabular lever ledger and dead-lever guard were switched off for the prompt family on Day 3 rather than mistranslated, which was right with no evidence. The STS-B run on 2026-08-11 is the evidence: iterations 2, 3 and 4 were three refinements of one scale-definition lever, all three scored below iteration 1, and nothing stopped the repeat. The duplicate gate hashes the prompt TEXT, so two wordings of the same move pass it — the two rejections it did fire in that run were baseline re-briefs. Nothing is wasted silently (every attempt is scored, recorded, and the winner still banks), but roughly three of four iterations bought nothing. The prompt family needs its own notion of a lever class before a guard can name one. |
| Literature grounding is retrieval over OpenAlex + arXiv only, and reaches the run only when the supervisor asks for it (plus always on iteration 1, capped per run). | **by-design** | Both are keyless and free, so `pip install iterate-ai` needs no account. papers-with-code, named in the original plan, was shut down and now redirects to HuggingFace; OpenAlex replaced it and covers ~320M works against arXiv's ~2.4M preprints. A citation is always an identifier the API returned: the model selects a paper by INDEX and the harness resolves it, so a DOI that was never fetched cannot be emitted. `--no-research` skips the specialist entirely for offline or fast runs. |
| Per-iteration history fed to the proposer is description + score + recent stdout — not a distilled insight, so context grows with run length. | **lifted in v0.2** (cell-by-cell path) | The Summarizer (pulled forward from v0.4) digests each finished experiment once (~150 tokens: techniques, data insights, what helped/hurt, takeaway); the supervisor reads all digests + a technique scoreboard + a lever ledger, never the notebooks. The one-shot `--spec` path keeps the old shape. |
| The Summarizer costs one extra LLM call per finished experiment, and a failed call silently degrades the digest to its deterministic skeleton (components + score + validation trail, no insight fields). | **by-design** | Degrading beats crashing: a digest is a nice-to-have for the next brief, never worth failing a recorded run. Observed once live (1/10 digests skeleton-only); a deterministic takeaway is now synthesized so the field is never empty. As of v0.4 the skeleton is read off `core.dossier`, which observes strictly more than the skeleton carries (data facts the cells printed, error signatures, session shape). Seeding those extra fields into the digest was BUILT AND REVERTED in v0.5. A same-model before/after on churn (gemma4:12b, 6 iterations per arm) held lever diversity at 5 distinct classes in both arms, but grew the planning context 23% in data_insights and 44% in what_hurt, and the score fell 0.6651 to 0.6507. No measured benefit and a regression in the direction the June EDA-ledger revert predicts, so it did not ship. Re-homed to v0.6 with 3 repeats per arm; n=1 cannot separate the change from a 12B's run-to-run variance, which is why it is re-homed rather than closed. |
| A probability-primary metric (`average_precision`, `roc_auc`, `log_loss`) could not be scored on the `--sandbox e2b` code path before v0.5. | **fixed in v0.5** | `build_code_job` listed only `predictions.csv` as a collected output, so the `probabilities.csv` the script correctly wrote was dropped and every such candidate scored as a hard failure. The live cell-by-cell path (the default) was never affected. It survived two releases because nothing tested `ModelTarget`'s `SupportsCodeGen` methods; there are now tests that do. |
| `core.dossier`'s data-fact extraction is heuristic: a printed line counts as a data fact if it carries a shape tuple or names a data property. It will miss a fact phrased unusually and can keep a line that merely mentions "rows". | **by-design** | The guarantee it does make is the one that matters for a fallback: facts are quoted verbatim from stdout, never paraphrased or inferred, so a dossier can be incomplete but cannot be wrong. Recall is a nice-to-have; invention would make it unusable as the Summarizer's fallback. |
| "Auditable report" = persistent memory + a runnable notebook per experiment (Day 6), not a prose report doc. | ~v0.10 | The notebook deliverable covers "what it tried + a runnable winner"; a dedicated prose Reporter is a later backlog item. |
| No `iterate history` / `best` / `why-failed` query commands. | backlog | The data is in Memory, and v0.3's in-run Q&A covers the live case; the offline CLI surface is a small add tracked on the backlog. |

## Interactive runs (v0.3)

| Limitation (today) | Lifted at | Notes |
|---|---|---|
| Messages take effect at the next safe boundary (a cell finishing, or just before planning), never mid-cell. The ack is instant; delivery can lag a slow cell or a slow LLM turn. | **by-design** | An interrupt is a kill, not a pause; the cell boundary is where state is coherent, gates run, and the kernel survives. |
| Only the bare words `pause` / `resume` / `stop` are controls (trailing punctuation tolerated). "please stop the run" routes as guidance, with only the ack text hinting otherwise. | monitor | The intent router deliberately has no stop authority: a misclassified sentence must never be able to end a run. |
| Message intent is classified by the same (possibly small, local) model that supervises. A failed or garbled classification defaults to the least-destructive route: a steer for the work in front of us, and the console says so. | **by-design** | Interpretation degrades, it never crashes or blocks the run. |
| Standing rules are run-scoped (they do not survive a restart) and lean-capped: 3 rules, 90 chars each; steers cap at 200 chars per message. | persistence: backlog | Dense injected context measurably regresses small models (the reverted EDA-ledger experiment); the caps are a feature. |
| In-run Q&A answers from the CURRENT run's experiments only; it cannot answer about previous runs. | TBD | Deliberate: iteration numbers restart every run, and cross-run answers were confidently wrong. An offline query surface is on the backlog. |
| Token-level streaming of the model's output did not ship (planned for v0.3, cut for the release). | backlog | The transcript streams per cell and per event, not per token. |
| The `--spec` fast lane stays non-interactive. | **by-design** | The frozen v0.1 path is kept cheap and predictable. |
| The interactive UI needs a foreground terminal; piped, scripted, CI, and backgrounded (`... &`) runs are plain and non-interactive. | **by-design** | A backgrounded process reading its terminal would be suspended by the OS; iterate detects this and stays hands-off. |

## Permanent by design (not limitations to remove)

- **Never execute user-provided source code.** A `--source` notebook/script is read as text only and reconstructed; the sandbox runs the agent's OWN generated code, never the user's. (Security policy.)
- **The harness/loop is bounded.** Human-approval gates and bounded autonomy are features, not limits to remove.
